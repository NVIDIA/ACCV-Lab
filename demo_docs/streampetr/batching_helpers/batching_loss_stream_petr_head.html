Batching Loss — StreamPETR Head

This page documents the batched loss computation used by StreamPETRHeadBatched. It builds on the same approach as the focal head but extends it to multiple decoder layers, keeping the computation batched over both samples and layers while returning per-layer losses.

The reference head is already partially batched over samples: within each decoder layer, it concatenates the per-sample targets and invokes each classification and bounding-box loss function once. The optimized head does not newly batch those loss-function calls over samples. Instead, it batches the surrounding per-sample target preparation, keeps variable-length ground truth in RaggedBatch objects, computes assignment cost matrices in batches, and computes bounding-box loss only for matched prediction/target pairs. The SciPy Hungarian solver still handles each layer/sample entry separately. The optimized head additionally invokes the classification and bounding-box loss functions across all decoder layers at once, including the DN losses; the reference processes one layer at a time.

You can find the implementation in the repository here:

  • StreamPETRHeadBatched: demos/streampetr/projects/mmdet3d_plugin/models/dense_heads/streampetr_head_batched.py

  • StreamPETRHead (reference): demos/streampetr/projects/mmdet3d_plugin/models/dense_heads/streampetr_head.py

  • Helper classes:

    • HungarianAssigner3DBatched: demos/streampetr/projects/mmdet3d_plugin/core/bbox/assigners/hungarian_assigner_3d_batched.py

    • HungarianAssigner3D (non-batched reference): demos/streampetr/projects/mmdet3d_plugin/core/bbox/assigners/hungarian_assigner_3d.py

Note

The used HungarianAssigner3DBatched follows the same approach as the HungarianAssigner2DBatched, with some changes in the cost matrix computation (but still using the same approach to compute the matrices). For more details, please also see the source code of the HungarianAssigner3DBatched and the page on the matching implementation.

Overview and Goals

The more fully batched loss computation is based on the same approach as used in focal_head_batched.py. Please, see the notes in focal_head_batched.py first for a detailed explanation of the approach.

The original StreamPETR head already batches the final classification and bounding-box loss-function calls over samples within each decoder layer: it concatenates the per-sample targets and flattens the sample and query dimensions before invoking the loss functions. The changes here instead batch the surrounding target preparation and cost-matrix computation over samples and decoder layers, preserve the structured batch dimensions until the loss-function boundary, and compute bounding-box loss only for matched prediction/target pairs. The SciPy Hungarian solver itself still runs separately for each layer/sample entry. The changes also add batching of the loss-function calls across decoder layers, including the DN losses, which is not present in the original implementation.

Here, we extend the approach to the case of multiple decoder layers, where the loss is computed for each decoder layer (i.e. batched, but not reduced over the layers). The explanation here is focused on this extension. The extension is done as follows:

  1. The GT data is duplicated for each decoder layer to match the shape of the predictions. This is similar to the original implementation. However, lists are used there. Here, we use RaggedBatch instances. After converting the GT data to RaggedBatch objects, an additional batch dimension is added, and the GT data is duplicated for each decoder layer, so that the additional batch dimension iterates over the decoder layers.

  2. The method _compute_per_layer_loss() is used as a wrapper around the actual loss functions and allows for reduction of the loss over the samples while retaining the per-decoder-layer separation. Note that this is done to work around the fact that the loss functions can only reduce over all objects in the batch at once, but cannot return per-sample losses, i.e. they cannot reduce over the objects only, keeping the batch dimension(s) intact.

Also note that the loss computation includes the DN loss computation (dn_loss_batched()), which is not present for the focal head. The inputs for the DN loss computation are obtained from prepare_for_loss(), which returns the data with the first dimension being the decoder layers, so that the inputs can be directly used for batched loss computation.

The implementation of the loss computation is done in the loss() function. Please see the notes & doc-strings there and in the related functions called from there for more details.

Below, we discuss the implementation in detail, focusing on the parts of the implementation that differ from or extend the focal head case.

DN Loss (Batched over Layers) & Build Loss Dictionary

When DN is enabled, DN losses are also computed batched over decoder layers and merged into the dictionary. Note that in the original implementation, the dn_loss_single() function is called for each decoder layer separately. Here, we implement dn_loss_batched() to compute the DN loss batched over all decoder layers.

Other Notable Implementations Changes

In this section, we discussed the changes needed to implement the batched loss computation for the StreamPETR head.

In addition to the changes discussed above, there are some other notable changes to the implementation. Please refer to the source code (streampetr_head_batched.py, see beginning of this page) for more details. Changes not discussed above in detail are:

  • The dn_loss_batched() method is used to compute the DN loss batched over all decoder layers. As the GT data is of uniform size, there is not need to use the RaggedBatch data format. However, the implementation is similar to loss_batched() in that the GT data is repeated for the individual decoder layers, and the loss is computed in a batched manner.

  • The _compute_per_layer_loss() method is used to compute the loss for the individual decoder layers. This is achieved by disabling the reduction in the called loss function, and performing the reduction after the call in _compute_per_layer_loss() instead. In this way, we can decide over which dimensions to reduce, allowing us to keep the batch dimension corresponding to the decoder layers intact, while reducing over the individual samples. Note that the type of reduction can still be configured for the loss function, and the configuration will be read and applied accordingly in the _compute_per_layer_loss() method.
