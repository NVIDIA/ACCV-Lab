Replacing the Data Loader

The DALI pipeline for StreamPETR is created using the pipeline described in the StreamPETR Pipeline example (including the pipeline itself, the custom processing step, and the custom post-processing function). It also uses the NuScenes loading implementation described in Data Loading for NuScenes.

The goal is to replace the original PyTorch DataLoader (used for the training data loading) with the DALI pipeline. Note that we focus on the training data loading, and do not replace the validation data loading.

This page describes the changes needed to the training script to enable the use of the DALI pipeline.

See the Evaluation for the runtime and CPU usage gains from this integration and instructions for comparing it with the PyTorch data loader.

Note

This demo re-uses the StreamPETR pipeline setup already described in the StreamPETR Pipeline Setup example, and assumes that the pipeline_setup module is available in the Python path. That example primarily describes the design and construction of the DALI pipeline. Please make sure that you are familiar with it before continuing here. This page focuses on the remaining integration work needed to use the completed pipeline inside the StreamPETR training implementation.

DALI Pipeline Setup

The major change is the creation of the DALI pipeline instead of a PyTorch Dataset. Both options are supported in our modified implementation, and can be enabled by setting the use_dali_pipeline flag to True in the used configuration file.

Adjustments to the Training Function

In the training script, we call custom_train_model() to train the model, which in turn calls custom_train_detector() (with the latter defined in projects/mmdet3d_plugin/core/apis/mmdet_train.py). The implementation of custom_train_detector() needs to be adjusted to handle the case that the passed dataset is actually a DALIStructuredOutputIterator object. Please see the code snippet below for details on how this is done.

demos/streampetr/projects/mmdet3d_plugin/core/apis/mmdet_train.py
 84    # ===== Using the DALI Iterator Directly (if used) =====
 85    #@NOTE 
 86    # If the passed dataset is a `DALIStructuredOutputIterator` object, use it directly instead of creating a 
 87    # PyTorch DataLoader from it.
 88    #
 89    # Note that the `else` branch is the original implementation. This means that if a PyTorch Dataset is
 90    # input, the behavior of the original implementation is preserved.
 91    if isinstance(dataset[0], DALIStructuredOutputIterator):
 92        data_loaders = dataset
 93    else:
 94        data_loaders = [
 95            build_dataloader(
 96                ds,
 97                cfg.data.samples_per_gpu,
 98                cfg.data.workers_per_gpu,
 99                # cfg.gpus will be ignored if distributed
100                len(cfg.gpu_ids),
101                dist=distributed,
102                seed=cfg.seed,
103                shuffler_sampler=cfg.data.shuffler_sampler,  # dict(type='DistributedGroupSampler'),
104                nonshuffler_sampler=cfg.data.nonshuffler_sampler,  # dict(type='DistributedSampler'),
105                runner_type=cfg.runner,
106                # Use unsharded mini-dataset sampling for the evaluation. This does not represent the real training use-case,
107                # but enables the use of the mini-dataset for performance evaluations.
108                replicate_dataset_per_gpu=cfg.get('data_loading_config', {}).get(
109                    'replicate_dataset_per_gpu', False),
110            ) for ds in dataset
111        ]
112    # ===== End of Using the DALI Iterator Directly (if used) =====

Important

Note that from this point on, the DALIStructuredOutputIterator acts as a drop-in replacement for the original PyTorch DataLoader (in case DALI is used), and no changes deeper in the training code are needed to switch from the original PyTorch DataLoader to the DALI pipeline.

Note

Mini-dataset replication. The performance configurations set data_loading_config.replicate_dataset_per_gpu=True for both loaders because NuScenes mini has too few sequences for the global batch size. This lets each GPU sample the full dataset. It is an evaluation setting, not a required step when integrating DALI into another project; the option defaults to False.

In tools/train.py, get_dali_pipeline_distributed_args() passes rank=0 and world_size=1 to the pipeline setup, while keeping device_id=local_rank. DDP continues to use the real distributed ranks.

For PyTorch, core/apis/mmdet_train.py forwards the flag to datasets/builder.py, which passes rank=0 and num_replicas=1 to the training sequence sampler. Worker initialization still uses the real rank, and validation retains its normal sampler. See the evaluation’s replication policy for the workload and augmentation-seed limitations.
