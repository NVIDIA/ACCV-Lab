Runtime Performance Evaluation and NVTX Profiling

This page explains how to use the optim_test_tools to measure runtime and add NVTX ranges for profiling. We focus on the most important measurements for the training iteration and loss/optimizer computation.

We rely on two singletons from accvlab.optim_test_tools:

  • Stopwatch: lightweight runtime measurements with optional CPU usage sampling

  • NVTXRangeWrapper: NVTX push/pop helpers with additional functionality to annotate critical sections for Nsight Systems (& Nsight Compute).

Enable & Configure in the Training Script

The configuration is centralized in the main training script (demos/streampetr/tools/train.py). The runtime measurement and NVTX range wrapper are enabled based on the runtime_meas_config section in the config. The use of the configuration file enables us to use different configurations for different types of runs, e.g.:

  • Training (actual usage): All disabled

  • Evaluation: Only Stopwatch enabled

  • Profiling: All enabled, nvtx range mismatches not checked (to avoid overhead)

  • (Debugging: All enabled, nvtx range mismatches checked (to help debugging range mismatches))

Note that the Stopwatch and NVTXRangeWrapper are enabled & configured centrally here, and can be used throughout the codebase relying on this configuration.

demos/streampetr/tools/train.py
281    # ===== Runtime Measurement & Profiling Configuration =====
282    #@NOTE
283    # Whether to use the runtime measurements and the nvtx ranges is configurable. Here, we read the
284    # configuration from the config file and enable the corresponding signletons if needed.
285    runtime_meas_cfg = cfg.get("runtime_meas_config", None)

Measuring the Training Iteration

The core iteration timings are implemented in the custom runner (IterBasedRunnerWithTime) to capture the outer training loop and the inner training step, including optional CPU usage measurement. Note that this means that this runner needs to be used instead of the original implementation (from the mmcv package) to enable the runtime measurements. The selection can be done by setting runner.type in the config file to IterBasedRunnerWithTime.

Outer loop timing with CPU usage sampling in run():

Measuring Optimizer/Loss Step and NVTX Ranges

The optimizer step is instrumented with both Stopwatch and NVTXRangeWrapper to annotate and time the critical loss backward/step section. Note that similar to the runner, this implementation needs to be used instead of the original implementation by setting up the optimizer_config parameter in the config file with type='Fp16OptimizerHookWithTime'.

demos/streampetr/projects/mmdet3d_plugin/core/adjusted_impl/optimizer_with_time.py

NVTX ranges also identify operations in the matching implementation and the loss computations described in the Batching Helpers demo.

NVTX Range Mismatch Checking

To enable NVTX range mismatch checking, set both enable and keep_track_of_range_order to True in runtime_meas_config.nvtx_range_wrapper. When checking is enabled, calls to range_pop(expected_name) verify that the range being closed has the expected name. Disable keep_track_of_range_order during performance profiling to avoid the checking overhead. For example, HungarianAssigner2DBatched checks its outermost range when the assignment finishes:

demos/streampetr/projects/mmdet3d_plugin/core/bbox/assigners/hungarian_assigner_2d_batched.py
320        #@NOTE: Types of range pops
321        #@NOTE: A simple range pop to close the NVTX range, without mismatch checking.
322        nvtx_wrp.range_pop()
323        #@NOTE: This will check for range stack mismatches if checking is enabled (enable only for debugging).
324        nvtx_wrp.range_pop("HungarianAssigner2DBatched.assign")

Viewing Results

  • Stopwatch results are printed from the main script at the end of training:

    demos/streampetr/tools/train.py
    521    # ===== Stopwatch: Print eval times =====
522    #@NOTE
523    # Print the run-time measurements at the end of the training. Note that depending on the setup, the 
524    # measurements will also be printed periodically (e.g. every 50 iterations). Here, we ensure that the
525    # last printed measurement is for the complete training.
526    stopwatch.print_eval_times()
527    # ===== End of Stopwatch: Print eval times =====

  • For NVTX, launch your run under Nsight Systems/Compute. The training script additionally uses torch.cuda.cudart().cudaProfilerStart() and torch.cuda.cudart().cudaProfilerStop() to start and stop the profiling session. Note that this is done only if the use of NVTX is enabled in the config (and therefore, the NVTX range wrapper is enabled).
